# Outcome planning in gatectl delivery

The delivery skill already controls check ordering. Add the missing planning guidance there so an
agent chooses a useful stage, checks material source assumptions before expensive implementation,
and raises genuinely missing owner decisions before dependent work. Reuse the current spec and
prior verified progress; no extra gate, document, review or approval ceremony is introduced.

Before final fast-workflow checks, finish the intended implementation, test code, documentation
and available real-source validation. Required policy checks and justified reruns remain binding.
Planning guidance does not turn a gate receipt into proof of product completeness.

Validation: skill frontmatter/scaffold validation, manual review for the small-edit case, an
integration with uncertain source data, and a task with an unanswered owner decision; repository
policy gates. No artificial RED or implementation-mirroring wording test for a prose-only change.

Local activation: reinstall this marketplace's plugin and replace the personal plan-to-finish
instruction with the gatectl delivery skill. Keep plain-language-context as the separate user
communication preference. Local installation is distinct from publishing a plugin release.
